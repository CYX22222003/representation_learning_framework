# LSTM Baseline — v5 Epoch Sweep Summary

**Date:** 2026-06-21
**Runs:** `2026-06-21-v5-e15`, `-e20`, `-e25`, `-e50`, `-e100`
**Seed:** 0 (identical across all runs)

## Purpose

Characterize how the stacked LSTM behaves under different training durations on the Polymarket 4h close-only dataset. This sweep is **not** for selecting a best epoch count — it's for describing the model's behaviour across training budgets. Results are reported for **every** run; no hand-picking.

## Configuration (shared across all runs)

| Item | Value |
|---|---|
| Model | 3-layer stacked LSTM (50 → 30 → 20), Linear head |
| Loss | RMSE |
| Optimizer | Adam, lr=1e-3 |
| Batch size | 64 |
| Input | univariate close, `[batch, 64, 1]` |
| Splits | train/test only (per-contract chronological 80/20) |
| Train / Test samples | 109,841 / 27,500 |
| Seed | 0 (full: torch + numpy + random + CUDA + DataLoader generator) |
| Hardware | NVIDIA RTX 4060 Laptop GPU (CUDA 12.6) |

## Results

| Epochs | Final train RMSE | Test MAE | Test RMSE |
|---|---|---|---|
| 15 | 0.0224 | 0.0089 | 0.0166 |
| 20 | 0.0222 | 0.0072 | 0.0157 |
| 25 | 0.0219 | 0.0103 | 0.0171 |
| 50 | 0.0218 | 0.0116 | 0.0185 |
| 100 | 0.0214 | 0.0093 | 0.0167 |

## Training trajectory (shared up to epoch 10)

Because the seed is fixed and the only variable is total epochs, all runs see identical trajectories up to the smallest run's horizon:

| Epoch | Train RMSE (all runs) |
|---|---|
| 0 | 0.0444 |
| 5 | 0.0233 |
| 10 | 0.0225 |

Beyond epoch 10 the loss decays very slowly: 0.0224 (e=15) → 0.0222 (e=20) → 0.0219 (e=25) → 0.0218 (e=50) → 0.0214 (e=100). The marginal train improvement from 25 to 100 epochs is ~0.0005 RMSE — well below the noise floor.

## Observations

1. **Train loss flattens around epoch ~10–15.** Subsequent epochs improve train RMSE by single digits in the fourth decimal place. There is no meaningful undertraining beyond ~15 epochs.

2. **Test metrics are noise-dominated across this range.** Test MAE varies from 0.0072 (e=20) to 0.0116 (e=50) and back to 0.0093 (e=100) — non-monotonic. With seed fixed across runs, the only thing varying is the number of optimizer steps applied to the *same* trajectory. The bouncing test numbers therefore reflect how a single trajectory's checkpoint happens to sit relative to the test distribution, not a real training-budget effect.

3. **Honest single-budget reporting.** Picking any one of these as "the LSTM result" would be cherry-picking. A defensible quoted number for the LSTM baseline (under this seed and pipeline) is something like:
   - **MAE: 0.007–0.012** (range across budgets 15–100)
   - **RMSE: 0.016–0.018** (range across budgets 15–100)

4. **What's not characterized by this sweep:** seed variance, input-feature variance, and cross-contract generalization. Those are separate dimensions; see the README for the broader limits of this baseline.

## Conclusion

The LSTM baseline is **trained to convergence well before epoch 25** on this data. Extending training to 50 or 100 epochs neither meaningfully improves nor hurts test performance under this seed. For downstream framework comparison, any single epoch budget in [15, 25] is reasonable; the choice should be documented but not optimized on test metrics.
